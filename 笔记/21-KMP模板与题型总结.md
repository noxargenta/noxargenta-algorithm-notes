## 2. 先统一 `nxt` 的含义

对长度为 `m` 的模式串 `pat`：

- `nxt[0]=-1` 是哨兵，不是实际的前后缀长度。
- 对 `1 <= len <= m`，`nxt[len]` 是 `pat[0..len-1]` 的最长相等真前后缀长度。
- “真”表示不能取整个串，所以 `nxt[len] < len`。
- 匹配状态 `j` 表示已经匹配了模式串前 `j` 个字符，下一个应比较 `pat[j]`。

例如 `pat="ababa"`：

| 前缀长度 `len` | 0 | 1 | 2 | 3 | 4 | 5 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 前缀 | 空 | a | ab | aba | abab | ababa |
| `nxt[len]` | -1 | 0 | 0 | 1 | 2 | 3 |

### `nxt` 预处理模板

```cpp
vector<ll> kmp_pre(const string& pat){
    ll m=pat.size();
    vector<ll> nxt(m+1);
    ll i=0,j=-1;
    nxt[0]=-1;
    while(i<m){
        while(j!=-1 && pat[i]!=pat[j]){
            j=nxt[j];
        }
        nxt[++i]=++j;
    }
    return nxt;
}
```

这里的 `nxt[++i]=++j` 表示：找到能继续接上当前字符的 border 后，前缀长度和匹配长度一起增加。若失配一直退到 `-1`，递增后就是 `0`，因此也正确处理首字符失配。

`j!=-1` 必须放在 `&&` 左边，让短路求值避免访问 `pat[-1]`。数组要开 `m+1`，因为会写到 `nxt[m]`。

### 与另一种前缀函数写法的对应

比赛目录中的两个区间匹配文件使用的是 `pi` 风格，虽然变量也叫 `nxt`：

| 项目 | 长度式 `nxt` | 0-based 前缀函数 `pi` |
| :--- | :--- | :--- |
| 数组长度 | `m+1` | `m` |
| 初值 | `nxt[0]=-1` | `pi[0]=0` |
| 数组含义 | 长度为 `len` 的前缀的 border | 以位置 `i` 结尾的前缀的 border |
| 失配回退 | `j=nxt[j]` | `j=pi[j-1]`，要求 `j>0` |
| 完整匹配后回退 | `j=nxt[m]` | `j=pi[m-1]` |

两者满足 **`nxt[len]=pi[len-1]`（`len>=1`）**。不能只替换初值，保留另一套下标公式。

## 3. 普通匹配：P3375

下面返回全部 **0-based** 起点，假设模式串非空；完整程序补上常用头文件和 `#define ll long long` 即可。

```cpp
vector<ll> kmp_match(const string& s,const string& pat){
    ll n=s.size(),m=pat.size();
    auto nxt=kmp_pre(pat);
    vector<ll> pos;
    ll i=0,j=0;
    while(i<n){
        while(j!=-1 && s[i]!=pat[j]){
            j=nxt[j];
        }
        i++;j++;
        if(j==m){
            pos.push_back(i-m);
            j=nxt[j];
        }
    }
    return pos;
}
```

- `i` 已指向匹配末尾的后一位，因此 0-based 起点是 `i-m`，P3375 输出时再加 `1`。
- 匹配成功后回退到 `nxt[m]`，保留可用后缀。例如 `aba` 在 `ababa` 中出现两次，不能直接清零漏掉重叠。
- P3375 还要求输出 `nxt[1..m]`；源码中的计数返回值不是该题最终输出的一部分。
- 预处理 O(m)，线性扫描 O(n)，保存所有匹配位置最多 O(n) 空间。

## 4. 循环移位：Shift String

等长字符串 `s`、`t` 中，`t` 是 `s` 的某个循环移位，当且仅当它出现在 `s+s` 中。查找第一个匹配起点即可得到一个对应的左移量。

例如 `s="abcd"`、`t="cdab"`，在 `abcdabcd` 中首次出现的起点为 `2`。

当前代码的特点与前提：

1. 用 `s1+=s1` 构造文本，找到第一次匹配后立即返回 `i-m`。
2. 用全局 `ok` 标记是否找到，每组开头已执行 `ok=0`。也可以只根据返回值是否为 `-1` 判断。
3. 如果题意是循环移位，必须保证两串原长度相同；当前代码没有主动检查等长。
4. 返回值是左移量；如果题目问右移量，需要按题意换算，不能直接混用。

总时间和空间均为 O(n)，这里 `n` 是原字符串长度。

## 5. 周期：P4391 无线传输

设 `b=nxt[n]`，那么最短周期长度为：

```cpp
ll p=n-nxt[n];
```

因为长度为 `b` 的前后缀相等，意味着 `s[i]=s[i-p]` 对 `p<=i<n` 成立；最长 border 对应最短周期。

**“周期”与“完整重复单元”要分开：**

| 问题 | 判断方式 | 例子 |
| :--- | :--- | :--- |
| 原串是某个无限重复串的前缀 | 直接取 `p=n-nxt[n]` | `ababa` 的最短周期是 `2` |
| 原串由一个短串完整重复组成 | 还要求 `n%p==0`；若要求至少重复两次，还需 `p<n` | `ababa` 不能被 `ab` 完整拼成 |

当前 P4391 代码直接输出 `n-next[n]`，对应允许末尾只保留部分周期的模型。时间 O(n)，空间 O(n)。

## 6. 数列整体平移：差分 KMP

### CF471D：消去整体加法

若一个窗口满足 `a[l+i]=b[i]+c`，相邻作差后常数 `c` 被消去：

```text
a[l+i+1]-a[l+i] = b[i+1]-b[i]
```

因此对长度为 `n-1` 的 `difa` 和长度为 `m-1` 的 `difb` 做 KMP；KMP 只要求能判等，不限于字符。

- 模式原长度 `m==1` 时，每个位置都能通过整体平移匹配，答案是 `n`，不要进入空模式 KMP。
- `m>n` 时答案为 `0`。
- 当前源码把 `difb` 作为模式传入，`difa` 作为文本传入；局部变量名 `s,p,nn,mm` 比较容易读反。
- 当前源码的 `nxt` 按文本长度开辟；若允许 `m>n`，预处理可能越界。通用整理时应先特判 `m>n`，或始终按模式长度分配 `nxt`。
- lambda 参数可改为 `const vector<ll>&`，避免复制整个差分数组。

时间 O(n+m)，空间 O(n+m)。做差时也要确认原始数值范围，`ll` 不能保证任意输入差值都不溢出。

### Harmonious subarrays：多次区间询问

仓库中有[旧版](../competition/2026江西八校集训联盟第二场联赛/Harmonious_subarrays.cpp)和[改进版 `2.cpp`](../competition/2026江西八校集训联盟第二场联赛/2.cpp)。改进版先全局匹配，再记录每个 **起点** 是否匹配：

```text
is_match[x] = 差分模式是否从差分文本的 0-based 位置 x 开始出现
pre[k] = is_match[0..k-1] 的和
```

询问原数组的 1-based 区间 `[l,r]`，原模式长度为 `m`：

- 区间长度小于 `m`：答案为 `0`。
- `m==1`：答案为 `r-l+1`。
- 其余情况，原数组合法起点是 `[l,r-m+1]`，转成差分数组 0-based 起点是 `[l-1,r-m]`。

所以答案为：

```cpp
pre[r-m+1]-pre[l-1]
```

预处理 O(n+m)，每次询问 O(1)，总时间 O(n+m+q)。

旧版的教训：构造 `b` 的差分时误用了 `i<n`，应为 `i<m`；将数值差分强行加入 `string` 会窄化为字符、丢失信息；`prea` 是 0-based，而查询下标是 1-based。逐次重跑匹配还会重复扫描，应优先使用 `2.cpp` 的数值数组与前缀和思路。

## 7. 删除模式串：P4824 的状态回滚

不能先标出原串所有匹配再统一删除，因为删除后两边会拼接，产生新的匹配。正确做法是边扫描边维护结果栈。

源代码在 `Node.j` 中保存的是 **处理当前字符前、完成失配回退后的 `j`**，所以这个字符被接上后的状态是 `Node.j+1`。删除模式串后，恢复方式为：

```cpp
j=st.empty() ? 0 : st.top().j+1;
```

更容易记忆的等价方式是直接保存“处理完该字符后的状态”：

```cpp
string ans;
vector<ll> state;
ll j=0,m=pat.size();
for(char c : s){
    while(j!=-1 && c!=pat[j])j=nxt[j];
    j++;
    ans.push_back(c);
    state.push_back(j);
    if(j==m){
        ans.resize(ans.size()-m);
        state.resize(state.size()-m);
        j=state.empty() ? 0 : state.back();
    }
}
```

这个片段依赖非空 `pat` 及其 `nxt`。**这里不是普通计数匹配：删除后必须取剩余结果的状态，不能直接令 `j=nxt[m]`。**

每个字符至多入栈、出栈一次，时间 O(|s|+|pat|)，空间 O(|s|+|pat|)。当前 `Node` 的 `i,c2` 不参与最终匹配和恢复，可以精简。

## 8. KMP 自动机：把回退预处理掉

`go[j][c]` 表示已经匹配长度为 `j`，再读一个字符 `c` 后的新长度。下面假设字符集为小写英文字母，`m=pat.size()`，`nxt` 已计算：

```cpp
vector<vector<ll>> go(m,vector<ll>(26));
for(ll i=0;i<m;i++){
    for(ll c=0;c<26;c++){
        char ch=char('a'+c);
        if(pat[i]==ch){
            go[i][c]=i+1;
        }else if(i==0){
            go[i][c]=0;
        }else {
            go[i][c]=go[nxt[i]][c];
        }
    }
}
```

这里 `i>0` 时有 `0<=nxt[i]<i`，依赖的行已经算好，所以预处理是 O(26m)，而不是对每个转移重新跑一遍回退。

只为 `0..m-1` 建表，但转移结果可以为 `m`。到达 `m` 后必须立即按题意处理，不能直接拿 `go[m]` 继续查。

### CF291E：树上继承状态

显式栈保存 `{节点编号, 已匹配长度}`：

1. 从根的 `{1,0}` 出发。
2. 每个孩子从父节点的 `now` 复制出自己的局部 `j`，逐字符处理边上的字符串。
3. 每次 `j==m` 就计数，并令 `j=nxt[m]`，保留重叠匹配。
4. 把处理后的 `{v,j}` 入栈；兄弟分支之间不能共用修改中的状态。

匹配可以跨过多条边；根到某个后代路径上的一次出现，在其最后字符所在位置计数，不会因为下面还有多个后代而重复计算同一个结束位置。

单一文本的 KMP 可以线性摊还回退；树上同一高状态可能被复制到很多分支，不能直接照搬这份摊还结论。自动机保证每个边字符 O(1) 转移。设所有边字符串总长为 `L`、节点数为 `n`，时间 O(26m+L+n)，包含输入存储的空间 O(26m+L+n)。

### LeetCode 1397：禁止子串的双边界 DP

状态是 `f[i][j][low][high]`：

| 维度 | 含义 |
| :--- | :--- |
| `i` | 已经填入的字符数 |
| `j` | 当前后缀与 `evil` 前缀匹配的长度 |
| `low` | 当前前缀是否仍与下界 `s1` 相等 |
| `high` | 当前前缀是否仍与上界 `s2` 相等 |

可选字符范围、下一状态与禁止条件：

```cpp
int l=low ? s1[i]-'a' : 0;
int r=high ? s2[i]-'a' : 25;
int nj=go[j][c];
if(nj==m)continue;
int nlow=low && (c==s1[i]-'a');
int nhigh=high && (c==s2[i]-'a');
```

**统计出现次数时，匹配完成后回退；禁止出现模式串时，匹配完成就丢弃分支。** 回退后继续会把已经出现 `evil` 的非法字符串算进去。

`i==n` 返回 `1`；记忆化数组用 `-1` 区分未计算与答案为 `0`。按 `1e9+7` 取模，时间 O(nm·26)，DP 空间 O(nm)，另有 O(26m) 自动机和 O(n) 递归栈。

当前源码的 `ll f[505][55][2][2]` 实际仍在函数内，是约 0.85 MiB 的局部数组；上方“作为成员变量”的注释与代码位置不一致。栈空间较小时应真正移为成员、静态存储或改用动态数组；固定维度也依赖原题范围。

## 9. 做题时的速查顺序

1. **确定匹配对象。** 原串、双倍串、差分数组，还是树上字符流？
2. **确定 `j` 的含义和 `nxt` 体系。** 已匹配长度；长度式和 `pi` 式不混用。
3. **确定完整匹配后的动作。** 计数回退、返回首个位置、删除并恢复栈状态，或 DP 中丢弃分支。
4. **检查边界。** 模式非空、`m==1`、`m>n`、重叠匹配、0/1-based 转换、多组状态清空。
5. **检查复用机会。** 多询问先全局匹配；多分支或 DP 先建自动机。

KMP 的应用主线可以归纳为：**最长 border → 失配回退 → 维护匹配长度 → 按题目改变状态的传递与处理方式。**
