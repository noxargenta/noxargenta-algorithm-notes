# 缓存 DP：基准费用与行最小值优化

题目：[C. To Cache, or Not to Cache（QOJ 25336）](https://qoj.ac/contest/4699/problem/25336)

两份实现的核心算法相同：**先扣除每次直接访问的基准费用，再用有序缓存状态做 DP，维护行最小值优化转移。** 下文按本地代码和注释整理模型；其中使用 `best` 的写法依赖 `B <= C`，具体数据范围以题面为准。

## 2. 问题模型与缓存顺序

有 `n` 次请求，地址编号在 `1..m`，缓存容量为 `2`。每次请求地址 `x` 时，可以选择：

| 选择 | 费用 | 对缓存的影响 |
| :--- | :--- | :--- |
| 直接访问 | `A` | 缓存内容与顺序均不变 |
| 通过缓存访问，且命中 | `B` | 把 `x` 变为最近使用的地址 |
| 通过缓存访问，但未命中 | `C` | 插入 `x`；缓存已满时淘汰较早使用的地址 |

目标是最小化全部请求的总费用。

用 `[u, v]` 表示缓存状态，`u` 是最近使用的地址，`v` 是较早使用的地址，`0` 表示空槽。初始状态为 `[0, 0]`。

- `[u, v]` 和 `[v, u]` 不能合并：下一次未命中时，淘汰的地址不同。
- 非零地址不能重复占两个槽，因此 `[x, x]` 不合法。
- 只有一个地址时写作 `[x, 0]`，不会出现 `[0, x]`。
- **只有选择通过缓存访问时才更新使用顺序**，直接访问不更新缓存。

## 3. 为什么先减掉每次的 `A`

如果直接用实际费用做 DP，每次直接访问都要给全部状态加上 `A`。但任意方案都处理了相同数量的请求，可以把这部分统一提出来。

设处理了 `i` 次请求，定义：

```text
相对费用 = 实际费用 - i * A
hit  = B - A
miss = C - A
```

于是三种操作的相对增量分别是：

- 直接访问：`0`。
- 缓存命中：`hit`。
- 缓存未命中：`miss`。

最终答案为 `n * A + 最小相对费用`。`hit`、`miss` 可以为负数，表示比直接访问更省钱。

这样，**所有旧状态都可以通过直接访问免费保留**，每次只需计算通过缓存访问产生的变化。

## 4. DP 状态与初值

```text
dp[u][v] = 处理完当前前缀后，缓存为 [u, v] 的最小相对费用
best[u]  = min(dp[u][v])，即第 u 行的最小值
ans      = min(dp[u][v])，即所有状态的最小值
```

初始时：

```cpp
dp[0][0] = best[0] = 0;
ans = 0;
// 其余 dp 和 best 都是 INF。
```

`0` 不是实际地址，因此第 `0` 行不会被请求更新，`best[0]` 始终为 `0`，代表此前一直直接访问、缓存仍为空。

## 5. 处理一次请求 `x`

一旦选择通过缓存访问，`x` 一定变成最近使用的地址，因此本次只会更新第 `x` 行。枚举最终保留下来的另一个地址 `y`，其中 `0 <= y <= m`、`y != x`。

以下公式右侧都表示本次请求之前的状态。

### 5.1 直接访问，保留 `[x, y]`

```cpp
ll value = dp[x][y];
```

相对费用不变。其他行也由直接访问原样保留，不必遍历。

### 5.2 命中，从 `[x, y]` 或 `[y, x]` 转移

这两个状态都包含 `x`，通过缓存访问后都会变成 `[x, y]`：

```cpp
ll hitBase = min(dp[x][y], dp[y][x]);
if (hitBase != INF) value = min(value, hitBase + hit);
```

例如缓存为 `[2, 1]`，请求 `1` 并选择缓存访问，结果就是 `[1, 2]`。

### 5.3 未命中，从 `[y, z]` 转移

若旧缓存为 `[y, z]` 且不包含 `x`，插入 `x` 后淘汰 `z`，得到 `[x, y]`。当 `y=0` 时，对应从空缓存插入 `x`。

朴素地枚举 `z`，一次请求需要 `O(m²)`；而转移只关心第 `y` 行的最小费用，可以尝试：

```cpp
if (best[y] != INF) value = min(value, best[y] + miss);
```

这里有一个必须解释的细节：**`best[y]` 可能来自 `[y, x]`，它实际是命中，不能当作一次真正的未命中。**

本写法在 `B <= C` 时仍然成立，因为 `hit <= miss`，而前面的命中转移已经提供了：

```text
dp[y][x] + hit <= dp[y][x] + miss
```

因此，不合法的“未命中候选”总被一个合法且不更贵的命中候选覆盖，不可能把答案错误地压低。其余不含 `x` 的行内状态本来就是合法来源。

**如果不满足 `B <= C`，不能直接套这个优化。** 届时需要在未命中来源中排除第二槽为 `x` 的状态，例如另行维护带下标的行最小值和次小值。

### 5.4 写回并维护最小值

```cpp
dp[x][y] = value;
best[x] = min(best[x], value);
```

处理完这一行后：

```cpp
ans = min(ans, best[x]);
```

旧的最优状态可以直接访问并保留，所以 `ans` 不会变大；只有第 `x` 行可能产生更小的值。

## 6. 为什么可以原地更新

处理固定的 `x` 时：

1. 只写 `dp[x][y]`，不会改动其他行。
2. `y != x`，因此读取的 `dp[y][x]` 和 `best[y]` 都来自其他行，仍是本次请求之前的值。
3. 当前单元格 `dp[x][y]` 只访问一次，先读再写，不会重复消费本次请求。
4. 虽然 `best[x]` 会边算边更新，但转移从不读取它，因为 `y == x` 已被跳过。

因此不需要另开 `ndp`，`y` 正序、倒序都可以。这里能省掉滚动数组的原因是读写依赖互不干扰，并非一般 DP 都能直接原地更新。

## 7. 整理后的完整代码

以下保留两份源码的核心转移，统一数组大小，并恢复读取测试组数 `T`。两份原始源码保留在上面的链接中。

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

const ll INF = LLONG_MAX;

void solve() {
    int n, m;
    ll A, B, C;
    cin >> n >> m >> A >> B >> C;

    const ll hit = B - A;
    const ll miss = C - A;
    vector<vector<ll>> dp(m + 1, vector<ll>(m + 1, INF));
    vector<ll> best(m + 1, INF);
    dp[0][0] = best[0] = 0;
    ll ans = 0;

    for (int i = 0; i < n; ++i) {
        int x;
        cin >> x;
        for (int y = 0; y <= m; ++y) {
            if (y == x) continue;

            // 直接访问：缓存 [x, y] 不变。
            ll value = dp[x][y];

            // 缓存命中：[x, y] 或 [y, x] -> [x, y]。
            ll hitBase = min(dp[x][y], dp[y][x]);
            if (hitBase != INF) value = min(value, hitBase + hit);

            // 缓存未命中：[y, z] -> [x, y]。
            // best[y] 包含 [y, x] 的情况由 hit <= miss 保证无害。
            if (best[y] != INF) value = min(value, best[y] + miss);

            dp[x][y] = value;
            best[x] = min(best[x], value);
        }
        ans = min(ans, best[x]);
    }

    cout << n * A + ans << '\n';
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T;
    cin >> T;
    while (T--) solve();
    return 0;
}
```

### 复杂度

- 初始化 `dp`：`O(m²)` 时间。
- 每个请求只枚举 `m+1` 个 `y`：转移总计 `O(nm)` 时间。
- 每组总时间 **`O(m² + nm)`**，空间 **`O(m²)`**。

相比每次扫描全部缓存状态，关键优化是“直接访问零增量保留旧状态 + 只更新请求地址所在行 + 行最小值”。

## 8. 本地样例与易错点

仓库 CPH 测试配置保存了下面四组数据：

```text
4
2 2 1 2 3
1 1
4 2 2 1 3
1 1 1 2
5 3 4 1 2
1 2 2 3 1
5 3 3 1 4
1 2 2 3 1
```

对应输出：

```text
2
7
9
13
```

第二组可以选择：第一次通过缓存访问 `1`，花费 `3`；之后两次命中，各花费 `1`；最后直接访问 `2`，花费 `2`，合计 `7`。这也说明不能对每次请求单独贪心选择眼前最便宜的访问方式。

- **测试组数要读入**：注释版源码当前关闭了这行读取，直接喂上述输入会把 `4` 误当作 `n`。
- **状态必须有序**：第一槽是最近通过缓存访问的地址，顺序决定未命中时保留谁。
- **跳过 `y == x`**：既避免重复地址，也保证原地更新时不读取刚更新的 `best[x]`。
- **不要对 `INF` 直接加费用**：`LLONG_MAX + 正数` 会溢出，两处转移都先判断可达。
- **费用使用 `long long`**：包括 `hit`、`miss`、DP 和最终的 `n * A`；实际费用与乘积也应在题面允许的数值范围内。
- **不要省略直接访问**：即使命中，也仍可选择直接访问且不改变缓存。
- **不要漏加基准费用**：`ans` 是相对费用，最后输出 `n * A + ans`。

## 9. 可以复用的思路

1. 每一步都有一项公共费用时，先扣掉公共部分，尝试把“不改变状态”的选择变成零增量。
2. 若操作后某个状态维度固定为当前输入，只更新这一行或这一列，避免扫描整个状态表。
3. 转移对某个维度只取最小时，维护行最小值；若把不合法来源也纳入最小值，必须证明它总被合法候选覆盖。
4. 判断能否原地更新时，明确每个读取来自旧层还是新层，再检查循环顺序。
